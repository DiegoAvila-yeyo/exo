## Design context (from `~/tesla/DASHBOARD_TERMINAL_DESIGN.md`, rounds 9-10, closed)

- **Terminal library**: `xterm.js`. **Vendor it locally, do not load it from a CDN.** This app already has a deliberate local-auth security model (token, Origin allow-list, CSRF) — pulling a script from a CDN at runtime would be a real inconsistency with that model (external network dependency, an origin we don't control serving executable code into this page). Download a specific pinned release of `xterm.js` (plus whatever minimal addons you actually need, e.g. the fit addon for resize) and embed it via Go's `//go:embed` so the whole frontend is served from the binary itself with zero runtime external requests. Record the exact version you vendored.
- **Connection UI states**: `connecting`, `ready`, `reconnecting`, `disconnected`, `session lost` — these map to the WS lifecycle (initial connect, the `{"type":"ready",...}` status message, a dropped connection while attempting to re-dial, a connection that won't come back, and a session that no longer exists server-side e.g. 404 on reconnect).
- **Cold-start behavior**: while waiting for the initial connection (which may be slow the very first time if `launchd` has to cold-start the backend — round 8), the terminal is **read-only** and does not locally buffer typed input — input is only sent once the `ready` status message arrives, matching what was already decided in round 9.
- **Ownership/control UI (round 10, important, don't skip this)**: when the session's current owner is `"agent"` (not this browser tab), the terminal must be **visually locked** — clearly indicate "Agent has control" (or similar), and **must not** silently drop keystrokes typed by the human, and **must not** auto-request takeover on the first keystroke either. Instead, typing/pasting while locked should surface an explicit "Take control" action the human has to deliberately click/confirm, which sends the `{"type":"takeover","owner":"human"}` control message already implemented server-side. Only after the server confirms via `{"type":"lease","owner":"human",...}` does the terminal become locally editable.
- **Resize**: debounce actual terminal resize events (~100ms, per round 9) before sending `{"type":"resize","cols":N,"rows":N}` — don't spam the server on every pixel of a drag-resize.
- **Reconnect + replay**: on reconnect (whether after a network blip or a fresh page load), the existing server-side ring buffer replay (already implemented — the first message(s) after `Subscribe`/`SubscribeWithLease` include buffered history) should just render into the terminal as scrollback; you don't need to build new replay logic, just make sure the frontend doesn't choke on receiving a possibly-large initial binary chunk before the live stream starts.
- **Session list/switcher**: this app supports multiple concurrent PTY sessions per backend (M3). The UI needs: a way to see existing sessions (`GET /api/sessions`), create a new one (`POST /api/sessions`, needs the double-submit CSRF token — the page already embeds it in `<meta name="nucleo-csrf">`), switch which one is currently displayed (only one visible terminal at a time is fine, per the round-9 decision — no need for multiple simultaneous visible panes), and close one (`POST /api/sessions/{id}/close`). Switching sessions means tearing down the current WS connection and opening a new one to `/api/terminal/{newID}/stream`.
